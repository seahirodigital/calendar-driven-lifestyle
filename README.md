# 予定日程付近グルメ（Calendar-Driven Gourmet）

自分の Google カレンダーの外出予定を読み取り、その予定の近くで入れる
ランチ・カフェ・お土産スイーツの候補を、食べログの評価だけで調べて
週表示してくれる Muse Space（Web アプリ）です。

予定がある日はその場所の近く、予定がない日は自分のホームエリアを
対象に、毎晩自動で候補を更新します。予約や購入は行わず、候補を
出すところまでが役割です。

## 特徴

- **評価ソースは食べログだけ**: 候補は食べログの点数 3.3 以上のみ。
  他サイトの点数は使いません。食べログのリンクは日本語版 URL に統一。
- **予算はハードルール**: 設定したランチ予算（初期値 2,000 円）を超える
  店は、フラグ付きで残すのではなく候補から除外して補充します。
- **営業時間・定休日を必ず表示**: 食べログ店舗ページの営業時間と定休日を
  候補ごとに保存し、その枠の利用時間帯（ランチ時間帯、または夜の予定の
  開始前）に開いていない可能性がある店には警告を付けます。
- **週表示（今週／来週／再来週）**: 月〜日の週単位で予定枠を表示。
  横スワイプでも週移動できます。各枠は「ランチ／カフェ／お土産スイーツ／
  行き方」のアコーディオン構成で、複数を同時に開けます。
- **写真で選ぶ**: ランチ・スイーツのカードにはその店自身の写真
  サムネイルを表示。写真タップで食べログの店舗ページへ、「地図を見る」
  で食べログ内の地図ページへ直接飛べます。
- **駅周辺カフェ DB**: カフェは駅単位でデータベース化し、一度調べた駅は
  再検索しません。チェーン店をブランド別プルダウンで表示し、全店舗に
  地図リンク付き。駅中（改札内・コンコース内・エキナカ・駅直結地下街）と
  駅外に分類して表示します。チェーンの店舗数は公式店舗検索で網羅確認
  するのが調査ルールです。
- **行き方**: 自宅最寄りの出発駅（2駅まで設定可）から目的地の駅までの
  経路を実検索で比較し、安い方を表示。外部の路線検索リンクは Yahoo!路線
  （予定のある枠は開始時刻に間に合う到着時刻指定）です。
- **自分の評価とフィードバックループ**: 行った店をカードから
  5点満点・0.1刻み＋メモで評価でき、店単位で保存。高評価の店は後の候補で
  優先、低評価（2.5以下）の店は候補から外れます。設定画面の「履歴」
  タブで、写真付きカード形式の履歴を点数ソートやキーワード検索
  （店名・場所・ジャンル・メモ）で探せて、CSV（ファイル名「過去履歴.csv」）
  にも書き出せます。履歴カードは左スワイプで削除でき、候補カードの
  評価表示と同期します。
- **共有**: 候補・履歴カードから、店名・場所・食べログリンク（評価済みは
  自分の点数も）を X / LINE で共有できます。
- **非表示リスト**: カードの「！」ボタンで店を永続的に非表示にでき、
  設定から戻せます。ホームエリアの枠は同一週（月〜日）で同じ店を
  繰り返し提案しません。
- **写真コンプリートとカレンダー連動**: 表示範囲（今日〜来週日曜）の
  全候補に写真が付いていることを完了条件とし、欠けは保存済みデータからの
  補完→差分だけの再調査で埋めます。カレンダーの予定追加・変更は
  5分間隔の軽い差分チェック（指紋比較のみ）で検知し、変わった枠だけを
  対象に候補を即時取得します。裏側の定型処理（差分検知・補完・集計）は
  サーバースクリプトで実行し、エージェントは新しい行き先の調査など
  判断が要る部分だけに使います。

## アーキテクチャ

Muse の TypeScript フルスタック Space（Web アーティファクト）です。

- `client/` — React クライアント（`client/src/App.tsx` が画面本体）
- `server/src/actions.ts` — サーバーアクション。カレンダー読み取りと
  食べログ調査は、リフレッシュ時にエージェントタスクを起動して行い、
  結果を `saveCandidates` 経由で検証・保存します。画面は保存済み
  データだけを表示します（クライアントは外部ソースを直接取得しません）。
- `server/src/privileged.ts` — ホスト側の特権ハンドラ。5分間隔の
  カレンダー差分チェックのために、本人のメインカレンダーだけを読み取り
  イベントの指紋（ID・タイトル・時刻・場所）だけを返します。
- `server/src/schema.ts` — Drizzle スキーマ
- `drizzle/` — SQLite マイグレーション（0001〜0013）
- `space.json` — Space のランタイム設定。毎晩 02:40（Asia/Tokyo）に
  `refreshSchedule` アクションを実行する定期更新を含みます。

調査の手順（カレンダー範囲の決め方、食べログ 3.3 以上・予算内のみ、
営業時間の取得、カフェ DB の育て方、経路の比較方法など）は
`server/src/actions.ts` の `startRefresh` が組み立てる調査ブリーフに
すべて含まれています。

## 導入方法（自分の環境で使う）

このリポジトリは、作者個人のデータベース・カレンダー・設定を
すべて取り除いた共有用のコピーです。各自の環境で独立して動きます。

1. **自分の Muse に取り込む**: このソース一式を、自分の Muse の
   Space（TypeScript フルスタック）として取り込んでください。
2. **自分の Google カレンダーを接続する**: アプリは接続したアカウントの
   **本人のメインカレンダーだけ**を読みます。他人が所有する共有
   カレンダーや祝日カレンダーは読みません。接続先や対象は各自の
   アカウントで完結します。
3. **データベースは空から作られる**: DB は `drizzle/` のマイグレーション
   から新規作成され、作者の候補・評価・履歴などのデータは一切
   含まれません。初回リフレッシュで、自分のカレンダーと自分の調査
   結果からデータが育ちます。
4. **自分の設定を入れる**:
   - `server/src/actions.ts` の冒頭にある `ADOPTER_CONFIG` に、自分の
     ホームエリア（予定のない日に探す駅とエリア名）、自宅最寄りの
     出発駅（2駅）、よく行く駅（カフェ DB の事前登録）を設定します。
     初期値はプレースホルダ（`○○駅` など）なので、必ず書き換えて
     ください。
   - アプリの設定画面で、好みのジャンル、ランチ予算、お土産スイーツの
     好みを設定します（初期値は一般的な候補からの仮置きです）。
5. **あとは毎晩の自動更新に任せる**: 定期更新がカレンダーを読み直し、
   行き先が増えるたびにカフェ DB や経路データが自分の分だけ
   蓄積されていきます。

## 注意

- 食べログの点数・営業時間・価格帯は調査時点のものです。閉店・移転の
  可能性もあるため、最新情報は各リンク先で確認してください。
- 経路の運賃・所要時間は路線検索で確認できた実数値だけを保存し、
  確認できないものは空欄にします（推測で埋めません）。
